PART 1: backend, GET /api/citizen/household (mdm-service/app/citizen_api.py, logic in app/citizen.py)
 - Same pattern as the other /api/citizen routes: the caller is identified by the sign-in token (aadhaarRef) through mdm.citizen_link, never by an id the caller sends. 404 with the existing "not linked" message when the sign-in has no person.
 - Household = the person, their spouse (mdm.relationship SPOUSE), their children (PARENT_OF where the person is the parent, any age), their parents (PARENT_OF where the person is the child), and anyone sharing a ration card number with them (source_record.ration_card, source pds_view). Reuse mdm-service/app/uc5.py household_members(cur, pid) if it fits; that function already exists, is tested, and has a cap on household size. Do not edit uc5.py; wrap it.
 - Return only: items [{person_ref (an opaque id valid only for this response, not the master id), name, relationship_to_me (SELF, SPOUSE, CHILD, PARENT, SAME_CARD), age_band (for example "0 to 1", "2 to 17", "18 to 59", "60 and over"), registered_via ("BIRTH_REGISTRATION" when the child's master record came from a crs BIRTH event registered in the last 90 days, otherwise null), on_ration_card (true/false for this person), added_on (date of that registration or null)}], ration_cards [masked: last 4 characters only], count.
 - Never return: income or certificate data, identity references, Aadhaar-like references, phone numbers, addresses, date of birth, consent state, any other person's sign-in link, or the master person id. A minor's name is returned only to a parent of that minor (relationship CHILD); someone who merely shares a ration card sees names of adult members only and "Member" for minors.
 - Ordering: SELF, SPOUSE, CHILD (youngest first), PARENT, SAME_CARD. Stable.
 - Telugu names: the response carries the name as stored plus name_te if the translation cache has one (use the existing translation helper the other citizen routes use; skip if there is none).
 - Tests (mdm-service/tests/test_citizen_household.py): (1) a parent sees the spouse and a newborn child, labelled CHILD with registered_via BIRTH_REGISTRATION; (2) the second parent sees the same child; (3) an unrelated citizen sees none of them (probe a father and son with the same name); (4) the response contains no income, identity, phone, address, dob or master person id keys anywhere (walk the JSON); (5) a ration card number is masked; (6) a minor is "Member" to a card-sharer who is not a parent; (7) an unlinked sign-in gets 404; (8) a department-scoped officer role cannot call it (it is a citizen route only; follow how other /api/citizen routes behave for non-citizen tokens); (9) cap respected for a household of 60 linked people.
