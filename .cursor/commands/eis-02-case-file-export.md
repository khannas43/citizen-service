# Case file export: evidence, decision and audit trail, ready for an audit or an RTI request

First read `.cursor/commands/eis-00-working-rules.md` and follow it.

## Goal
From a case, produce a self-contained "case file" an auditor can read or print: who and what the case is about, the evidence, the timeline, every decision and outcome, the verification, and the audit log.

## Contents of the file (in this order)
1. Header: case reference, title, domain, status, created and last updated, assignee.
2. The alerts: rule name (use the same names as `RULE_NAMES` in `officer-portal/src/screens/ExpenditureIntegrity.jsx`), severity, amount at stake, plain-language summary, and the evidence rows in the same readable form the case detail shows.
3. Timeline: the data behind `GET /v1/cases/{id}/timeline` (`CaseTimelineService`), as a dated table (not a drawing).
4. Decision: classification, reason text, whether a notice is required.
5. Outcomes recorded (type, reference, authoriser, date) and the verification (who, when, note).
6. Audit trail: every `integrity_audit_log` row in time order with actor role and action (`IntegrityAuditLogRepository`).
7. Footer: generated on, generated by (role, not a name), and a line "Demo data" when the case is from the seeded demo set (cases created before 2026-01-01 are demo).

## Build
- **Backend:** `GET /v1/cases/{id}/export?format=json|html` in `IntegrityController`. Read access to the case's domain is required (`access.requireRead`), so payroll files need payroll roles. Build it in a new `CaseFileService`, reusing `IntegrityCaseService.getCaseDetail` and `CaseTimelineService`. `html` returns one standalone, print-ready HTML document (inline CSS, A4 print styles, no external assets). `json` returns the same content as data. Mask bank accounts the way the timeline does (`DetectionEngineService.maskToken`); never include Aadhaar numbers.
- **Portal:** in the case detail add "Download case file" (HTML, opens in a new tab ready to print) and "Download data (JSON)". Use `fetch` with the officer token and a Blob URL, since the link needs the Authorization header.
- No new dependencies. Do not generate PDFs on the server; the browser's Print to PDF is enough.

## Tests
- Service: the export contains each section for a beneficiary case and a payroll case; bank accounts are masked; unknown case is 404; a SCHEME_DEPT user gets 403 for a payroll case; SENIOR_MGMT gets 403 everywhere.
- Portal: both buttons call the API and trigger a download.

## Live check
Export one beneficiary case (for example any Rule 802 case) and one payroll case, open the HTML in the browser and print-preview to confirm it fits A4 and reads cleanly.
